## Context

Microsoft Excel 的 Office.js 任务窗格运行在隔离的浏览器环境中，不能直接读取 `C:\Users\<user>\.codex\config.toml`，并受 HTTPS、同源和 CORS 约束。当前用户配置选择 `responses` 协议的自定义提供方，而其 `http://localhost:8080` 对浏览器预检返回拒绝，因此需要一个本地伴随服务承接配置读取、凭据保护和模型请求。

本项目包含三个边界：Excel WebView 负责界面和 Office.js 工具执行；回环地址 Node.js 服务负责配置、凭据和协议适配；模型提供方只接收完成当前任务所需的指令、工具定义和工具结果。工件、界面和运维说明使用简体中文。

## Goals / Non-Goals

**Goals:**

- 自动复用用户级 Codex 配置中的当前模型和 Responses 提供方。
- 在令牌不进入 Excel WebView、工作簿内容不持久化到磁盘的前提下完成多轮工具调用。
- 支持工作簿读取、值和公式写入、格式、表格、图表、排序及工作表管理。
- 支持逐项审批和先告知后自动执行两种明确区分的修改模式，并在拒绝、协议异常或工具异常时失败关闭。
- 让用户在输入区直接切换模型与思考等级、查看上下文占用并提交文本任务，并从设置页选择系统 Codex 配置或长期自定义提供方。
- 让自定义提供方使用一个 API 根地址和显式协议，自动组成 OpenAI Responses、OpenAI Chat Completions、Anthropic Messages 或 Google Gemini generateContent 的版本路径、模型发现路径和认证请求头。
- 在每次任务窗格启动后对当前模型提供方执行无内容、短超时的连通性测试，并将成功或失败明确反馈到模型选择器和设置入口。
- 使用 Windows 当前用户 DPAPI 长期保存自定义密钥与模式选择，服务重启或切换系统 Codex 配置时不丢失自定义字段。
- 提供操作记录驱动的历史上下文视图；历史状态下继续对话或手动修改工作簿前必须确认。
- 提供可重复执行的 Windows 本地启动、侧载、验证和移除流程。

**Non-Goals:**

- 发布到 Microsoft Marketplace 或提供多用户云服务。
- 兼容 VBA、宏、Power Query、透视表或受保护工作簿的绕过操作。
- 自动读取或迁移任意第三方加载项的配置和会话。
- 对任意历史节点进行工作簿级无损快照、回滚或分支合并；历史记录只回到当时的任务窗格上下文，并明确保护后续修改。

## Decisions

### 使用 Office.js 任务窗格和本地伴随服务

任务窗格通过 `https://localhost:3210` 与同源 Node.js 服务通信，服务只绑定 `127.0.0.1`。相较 COM/VSTO 或 Excel-DNA，这个方案能使用 Excel 官方 JavaScript API、安装边界更小，也便于后续适配 Excel 网页端；代价是首次开发侧载需要本地 HTTPS 证书。

Windows 侧载先通过 Microsoft Office 开发工具注册清单并生成带 Web Extension 的临时工作簿，再从系统 App Paths 定位 `EXCEL.EXE`，以 `/x` 启动独立 Microsoft Excel 进程。这样不依赖 `.xlsx` 默认文件关联，避免 WPS 截获侧载工作簿。

### 系统配置与持久化自定义配置共用一个解析边界

审批偏好是与配置来源、最大步骤数同级的非敏感用户设置。它只接受 `required` 或 `auto`，缺失时默认为 `required`，随 `%APPDATA%\ChatExcel\settings.json` 保存和恢复。任务窗格通过独立的同源 JSON 接口更新该偏好，不复用要求完整提供方字段的设置保存接口；保存失败时前端恢复原选择，避免未持久化的状态开始任务。

本地服务默认每个模型步骤重新读取系统 Codex 配置。用户关闭“使用系统 Codex 配置”后，服务校验协议、API 根地址、API Key、模型 ID、上下文长度和思考等级。非密钥字段与模式选择写入 `%APPDATA%\ChatExcel\settings.json`；API Key 通过 Windows 当前用户 DPAPI 加密后才写入同一文件，任务窗格、状态响应、日志和浏览器存储都不返回明文或密文。服务启动时解密到进程内存，解密失败时按凭据未配置失败关闭。

系统模式和自定义模式是两个独立保存的配置槽。切换到系统模式只改变当前选择并持久化开关，不清空自定义协议、根地址、密钥、模型目录或模型参数；再次关闭开关时恢复上次有效自定义配置。

模型发现由本地服务按协议请求自动组成的模型列表端点。OpenAI 与 Anthropic 使用 `/v1/models`，Gemini 使用 `/v1beta/models`；认证头分别使用 Bearer、`x-api-key` 加 `anthropic-version`、`x-goog-api-key`。模型 ID 来自结构化响应，Gemini 的 `models/` 前缀在界面中移除；支持的思考等级优先读取提供方元数据，否则按模型族和协议使用保守映射。任务窗格只允许从发现结果或当前有效模型中选择模型 ID。

### 在任务窗格启动时探测当前提供方

任务窗格在成功读取脱敏配置后，由同源本地服务以当前生效的系统或自定义配置向对应的模型目录端点发起一次 `GET` 请求。探测只带协议所需认证头和 `Accept: application/json`，不发送提示词、工作簿内容、工具定义或生成请求，也不更新模型目录、保存配置或写入日志。探测使用独立的短超时；网络、认证、限流、HTTP 或响应格式失败均返回脱敏失败代码，不返回上游响应正文、接口地址或凭据。

任务窗格为每次探测分配递增标识，避免旧配置的慢响应覆盖用户刚保存的新配置状态。连通成功时模型选择器和设置齿轮显示绿色；失败时二者显示红色，但齿轮保持可用以便用户修正配置。状态通过按钮标题和无障碍标签给出安全的中文说明，不复用顶栏工作簿状态点，因为该点代表本地配置与工作簿状态而非上游提供方可达性。

### API 根地址和协议适配层

自定义 API URL 表示根地址，可以包含网关自有路径，但不要求用户填写 API 版本或具体方法。服务去除末尾斜杠以及已知的 `/v1`、`/v1beta` 和方法后缀，再按协议组成请求：

| 协议 | 生成端点 | 模型发现端点 |
| --- | --- | --- |
| OpenAI Responses | `/v1/responses` | `/v1/models` |
| OpenAI Chat Completions | `/v1/chat/completions` | `/v1/models` |
| Anthropic Messages | `/v1/messages` | `/v1/models` |
| Google Gemini generateContent | `/v1beta/models/{model}:generateContent` | `/v1beta/models` |

系统 Codex 配置继续遵循 `config.toml` 的 `base_url` 语义，只接受 `wire_api = "responses"` 并在该地址后追加 `/responses`，避免改变现有本机提供方行为。

服务会话仍保存 Responses 风格的规范化输入项。OpenAI Responses 原样发送；Chat Completions、Anthropic Messages 和 Gemini 适配器分别转换系统指令、用户文字、图片、工具定义、工具调用及工具结果，再把回答文字、调用 ID 和 usage 归一化回同一输出格式。这样审批、工具执行、步骤上限和会话校验不依赖上游协议。

### 服务端解析配置并保管凭据

服务优先从 `CODEX_HOME`，否则从用户目录下 `.codex/config.toml` 读取配置。每次模型步骤都重新读取文件，解析 `model_provider`、`model`、`model_reasoning_effort`、`model_verbosity`、对应的 `model_providers.<id>`、`base_url`、`wire_api` 及令牌来源。状态接口只返回脱敏字段。不会把令牌写入前端、日志、工作簿设置或浏览器存储。

### 使用无服务端会话存储的统一工具循环

每个会话在本地内存中保存规范化 `input` 数组。Responses 适配器发送 `store: false`、`parallel_tool_calls: false`、`include: ["reasoning.encrypted_content"]` 和严格函数定义，并保留完整输出项；其他适配器发送对应协议的完整消息历史、函数定义和串行工具偏好。Excel 执行工具后，前端返回与规范化 `call_id` 对应的 `function_call_output`，适配器转换为对应协议的工具结果后继续请求。模型步骤上限默认 100，可在设置页配置为 1 到 1000 并持久化；服务在每次继续循环前读取当前有效上限，达到上限时返回包含实际数值的错误并清理会话。会话还设置空闲过期时间，不依赖上游服务端会话存储。

此方式采用 OpenAI Responses 函数调用文档的无状态续传模式，并适配用户配置中的 `disable_response_storage`。

服务端继续为受信任的本地客户端兼容最多四张 PNG、JPEG 或 WebP 图片，并验证 data URL、单图和总大小，再由协议适配器转换为 `input_image`、Chat `image_url`、Anthropic base64 image source 或 Gemini `inlineData`。任务窗格不提供文件选择、预览或剪贴板图片入口。响应中的 token usage 与当前配置的上下文长度合成为脱敏上下文占用，供输入区显示；缺少 usage 时显示未知，不伪造精确比例。

模型和思考等级是会话的显式请求选项。输入区切换后，下一条用户消息及其后续工具步骤使用该选择；服务仍校验模型属于当前可选集合、思考等级属于当前模型映射。

### 工具协议在服务端和 Excel 端共享

`src/shared/excel-tools.js` 是工具名称、参数 Schema、可读标签及读取/修改分类的唯一来源。服务只把这些定义发送给模型；前端只执行已注册工具并再次校验参数。未知工具、无效 JSON、过大范围或尺寸不匹配全部返回结构化错误，不进行猜测性操作。

工作簿信息优先返回当前单元格范围；当图表等非单元格对象被选中且 Office.js 明确返回无效选区时，工具回退到活动单元格并在结果中标记选择模式。其他 Office.js 错误不触发回退。

### 修改操作按当前模式串行执行

读取型工具自动执行。需要审批模式下，写值、公式、格式、清除、建表、建图、排序和工作表变更必须显示工具名与参数并由用户批准或拒绝；无需审批模式下，任务窗格先显示明确告知，再执行一次对应工具。工具调用串行执行，结果以 `call_id` 精确回传；操作记录把实际执行摘要放在成功或失败状态之前。拒绝也作为工具结果返回模型，模型不得绕过当前模式。

### 任务窗格采用工作簿感知的上下布局

Excel Office.js 任务窗格的初始宽度由 Excel 宿主控制，清单和 `Office.addin.showAsTaskpane()` 都不能指定宽度。加载项不得添加不受支持的宽度字段；底部控制带在可用宽度不足以放下全部控件时先将审批和发送动作组换到下一行，保持所有控件可访问且不产生横向溢出。

ChatExcel 顶栏显示图标、名称、当前文件名与活动工作表组合标签和设置按钮。操作记录固定在对话上方，行高紧凑且可折叠；对话位于其下。输入框默认一行并随内容增长，底部控制条参考提供的 Codex/Claudian 界面排列模型、思考等级、上下文占用、停止/发送和审批模式，默认优先保持同一行；空闲提示以短小状态展示而非垂直撑满对话区。设置页同时提供配置来源、自定义协议和最大步骤数。面板使用半透明背景、轻量模糊、细边框和低半径，不用装饰性渐变或嵌套卡片。

模型选择器和设置齿轮还承担当前提供方连通性指示：任务窗格每次启动完成探测后，绿色表示当前提供方可达，红色表示探测失败。探测进行中保持中性色，不会禁用设置入口或阻止用户更正配置。

### 历史操作只回溯界面上下文并锁住后续修改

点击操作记录会选中对应时间点，并让对话区只显示当时已经发生的消息和操作状态。该行为不回滚工作簿。只要当前选中的记录不是最新记录，发送新对话前必须确认；确认后回到最新上下文，取消则保持历史视图。加载项订阅工作表变更事件；历史视图中检测到手动改单元格时弹窗，确认后保留修改并回到最新上下文，取消则尝试 Excel 原生撤销，撤销失败时保持锁定并报告错误。Agent 自身工具修改不会重复触发这类手动修改提示。

### 会话不持久化

聊天、工具结果和工作簿片段只保存在当前页面与服务进程内存中。刷新任务窗格或停止服务即清除会话。项目不包含遥测、云端中转或自动上传日志。

## Risks / Trade-offs

- [本地开发证书需要进入当前用户信任存储] → 使用 Microsoft Office 开发证书工具，安装说明明确作用域，并提供移除命令。
- [不同 Excel 版本的 Office.js 能力不一致] → 清单声明最低 API 集，运行时对表格、图表和范围图片等能力做错误返回，不降级为未知写入。
- [模型可能生成无效参数或重复修改] → 使用严格 Schema、禁用并行工具、限制步骤数、工具结果幂等提示和逐项确认。
- [大范围数据导致令牌和内存膨胀] → 读取工具限制最大单元格数，超限时要求模型缩小范围。
- [兼容图片输入放大请求和上下文] → 服务端限制数量、类型和尺寸并限制 JSON 请求体；任务窗格不暴露图片入口。
- [提供方模型目录和思考参数不统一] → 按协议解析结构化模型 ID，元数据缺失时使用标明为推断的保守映射；只发送该协议明确支持的思考字段，并把过高等级映射到最近的协议等级。
- [历史视图被误解为工作簿回滚] → 界面和文档明确标记“历史上下文”，不静默还原工作簿；所有后续修改通过确认锁保护。
- [自定义 API Key 泄露或残留] → 仅把 Windows 当前用户 DPAPI 密文写盘，明文不进入命令行参数、前端、日志或错误响应；持久化文件损坏或解密失败时不发送请求。
- [第三方网关宣称兼容但请求形状不完整] → 协议必须由用户显式选择，不按错误响应静默切换；测试用四个模拟提供方验证 URL、认证、图片、工具调用和工具结果形状。
- [本地网页可能尝试调用伴随服务] → 绑定回环地址、校验 `Origin` 和 `Host`、只接受 JSON、设置请求体上限且不开放通用代理。

## Migration Plan

1. 安装 Node.js 依赖并生成当前用户范围的 Office 开发证书。
2. 启动回环地址服务，验证 `/api/health` 和脱敏 `/api/config`。
3. 注册项目清单并在测试工作簿中打开任务窗格。
4. 先执行只读工具，再对隔离测试区域执行写值、公式、格式、表格和图表验收。
5. 回滚时注销清单、停止服务并按文档移除开发证书；用户工作簿不会依赖加载项才能打开。

## Compatibility Evidence

- 2026-08-01 对当前 `Sub2API`、`gpt-5.6-sol` 和 `/responses` 完成两步真实请求：提供方接受 `store: false`、严格函数 Schema、`include: ["reasoning.encrypted_content"]` 和 `parallel_tool_calls: false`；首步返回 `function_call`，追加完整输出及匹配 `call_id` 的 `function_call_output` 后返回最终 `message`。
- 当前用户配置的 `model_reasoning_effort = "max"` 在 120 秒内未完成首步；相同协议使用临时 `low` 推理强度在 22 秒内完成，因此运行时保留用户推理设置，同时把单步超时设为 300 秒。兼容性脚本不会修改用户配置。
