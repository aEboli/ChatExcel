## Context

恢复快照目前由会话内的 `checkpointTail` 串行保存。`suspend()` 在从活动会话表删除会话后才等待最终检查点，显式取消在这个窗口查不到会话，会直接清除文件，最终检查点随后可能再次保存快照。恢复锁近期改为硬链接候选文件和 `.reclaim` 标记，但标记创建、陈旧回收和普通释放仍存在检查到删除之间的窗口。

任务窗格已经在后续消息中提交当前 `workbookBinding`，但 HTTP 路由和 `SessionManager.addMessage()` 没有使用它。任务窗格目前在检测到绑定变化时会主动清除并重建会话；服务端仍必须将该字段作为 API 契约防线，以免其他调用方把恢复状态继续写到旧稳定标识。

## Goals / Non-Goals

**Goals:**

- 让挂起、普通取消和严格恢复清除共享同一会话收尾边界，确保取消返回后不存在迟到检查点可重建快照。
- 在收尾期间拒绝复用会话 ID，并让恢复、心跳先等待关联收尾结束。
- 在后续消息中验证并迁移稳定工作簿绑定，使下一检查点仅关联最新绑定。
- 让恢复锁的发布、释放和陈旧回收只删除 token 专属 owner 文件，不依赖对固定路径的非条件 `unlink`。
- 保持恢复文件加密、单快照和本地回环 API 的现有边界。

**Non-Goals:**

- 不改变任务窗格当前“另存为后清除旧会话并创建新会话”的产品流程。
- 不将恢复快照变成多工作簿历史，也不增加跨进程会话状态服务。
- 不对正在运行的旧版本服务实施无中断混合版本锁迁移。

## Decisions

### 会话收尾登记作为 ID 生命周期栅栏

`SessionManager` 增加私有的按 `sessionId` 收尾登记表。`suspend()` 在删除活动会话前创建并登记最终检查点的 promise；`cancel()` 和 `clearRecoverySession()` 无论会话在活动表还是收尾表，都先标记停止、等待该会话的 checkpoint tail，再清除恢复记录。登记清理按会话对象身份比较，避免旧收尾删除新会话的登记。

`start()` 发现同 ID 正在收尾时返回冲突。`restore()` 和 `touchRecovery()` 对匹配的收尾会话等待其完成；处于显式清除中的会话不返回可恢复内容。这个小型登记比全局互斥锁更窄，不阻塞无关会话。

### 后续消息迁移工作簿绑定

HTTP 的消息路由把 `workbookBinding` 原样交给 `addMessage()`。已有恢复绑定的会话在后续消息中必须收到有效稳定绑定；缺失或无效绑定在修改输入或调用提供方前失败关闭。新绑定不同于旧绑定时，更新会话中的绑定，下一次请求前检查点以新绑定覆盖唯一加密快照；不额外延长任务窗格心跳租约。

不把绑定变化视为一般会话冲突，因为恢复规格允许另存为后的稳定标识迁移；任务窗格是否保留原会话仍维持现有前端策略。

### 完整候选目录发布恢复锁

恢复锁改为同父目录中的候选目录，目录内先写入 `owner-<token>.json`，再将完整目录原子 rename 为主锁目录。持有者和陈旧回收者只读取、删除自己的 token 命名 owner 文件，并仅在该删除成功后调用空目录 `rmdir`。新的锁目录在发布时始终非空，因此旧持有者或延迟回收者无法删除后来发布的锁。

空的旧式目录锁仍仅在超过陈旧阈值后回收；有效但存活的 owner、无效 owner 或多个 owner 文件失败关闭。现有硬链接主锁和 `.reclaim` 文件锁仅作为旧格式读取；其陈旧转换先取得 token 专属候选目录过渡锁，再重新验证 owner 后原子移入唯一 quarantine，避免另一个回收者把转换期间新发布的目录锁误移走。旧格式仍活动或无法验证时保持不可用。

与继续补丁硬链接 `.reclaim` 相比，目录 owner 的路径绑定让删除操作天然指向已验证的 token，不需要为每一次条件删除再引入一层标记锁。

## Risks / Trade-offs

- [目录锁发布或删除受 Windows 文件占用短暂影响] → 保持有界重试；无法安全取得锁时返回恢复不可用，绝不删除快照。
- [严格清除失败后会话不再可用] → 保留收尾登记和绑定以供用户重试清除，但不允许继续模型请求或恢复泄露旧快照。
- [后续请求未携带稳定绑定] → 对已有恢复绑定的会话明确拒绝，防止静默回退到旧工作簿。
- [旧硬链接锁遗留] → 仅在确认陈旧且 owner 已退出后，通过过渡目录锁清理；无法确认时保留并失败关闭。

## Migration Plan

部署后，新锁以目录格式发布，旧的目录锁继续按兼容规则回收。若检测到陈旧的硬链接主锁或 `.reclaim` 文件锁，新版本用过渡目录锁串行化清理后再创建新目录锁；仍活动或无法验证的旧锁保持不可用状态。回滚到旧版本前应停止本地服务，避免混合版本同时操作同一恢复文件。
