## Context

任务窗格目前使用 `src/taskpane/taskpane.css` 集中控制聊天、操作记录、设置和底部输入区。400px 与 320px 窄视口已经没有横向溢出，但顶部栏、操作记录空态、消息气泡、输入区外框和固定页脚的垂直留白仍然占据较多空间。任务窗格是高频、窄宽度的工作界面，用户需要优先看到对话与工作簿结果。

## Goals / Non-Goals

**Goals:**

- 通过现有 CSS 规则收紧外层间距、固定区高度和组件内边距，让对话区获得更多可用高度。
- 正文消息保持 12px 字号和至少 17px 行高；辅助信息不低于现有可读下限。
- 保持桌面端常用按钮和可折叠行不小于 24px 高，并维持键盘焦点、滚动和 reduced-motion 语义。
- 在 400x900、320x700 视口下验证稳定布局和无横向滚动。

**Non-Goals:**

- 不改变任务窗格的 HTML 结构、JavaScript 状态、模型协议、Excel 工具或审批流程。
- 不改变任务窗格在 Excel 中的宿主宽度请求，也不使用全局缩放、浏览器缩放或新的运行时依赖。
- 不改变本地令牌边界、恢复数据或服务生命周期。

## Decisions

- **沿用集中 CSS 调整，而非全局缩放。** 直接降低外层 `gap`/`padding` 和固定区的 `min-height`，能保持文字像素清晰并让弹出菜单、焦点环和滚动容器继续按真实几何尺寸工作。全局 `transform: scale()` 会造成模糊、命中区域与视觉区域不一致，因此不采用。
- **优先收紧垂直留白，保留正文尺寸。** 顶部栏、操作记录标题/行、消息气泡和 composer 外框减少 2–5px 的垂直占用；消息字号维持 12px，只将行高由 18px 调到 17px。这样在高频阅读区域获得空间，同时不把辅助文案压到不可读。
- **为窄视口提供同一套紧凑基线。** `max-width: 439px` 下继续使用更小的外边距，并同步压缩顶部栏和页脚；不增加新的断点，避免 320px 与 400px 之间出现跳变。
- **固定交互下限。** mode/send、toolbar、section heading、activity rows 和菜单选项的高度保持在 24px 以上；附件删除按钮沿用现有视觉/键盘实现，不因本次密度调整缩小。

## Risks / Trade-offs

- [Risk] 操作记录展开后可见行数减少 → 维持现有内部滚动，并只降低单行留白，不移除步骤信息。
- [Risk] 更紧的输入区在长中文提示或附件状态下换行 → 保留 textarea 自动增高、附件横向滚动和 `min-width: 0`，并在两个窄视口实测。
- [Risk] 旧的布局断言锁定了固定高度 → 同步更新只涉及本次密度变化的断言与截图，不放宽横向溢出和可访问性断言。
