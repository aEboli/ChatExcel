## Context

`SessionManager` 当前在解析模型 `function_call` 时立即调用共享工具校验器。任何未知工具、无效 JSON、额外字段或范围语法错误都会抛出 `AgentSessionError`，外层随后删除会话。任务窗格从未收到工具调用，也没有机会把错误作为 `function_call_output` 返回给模型。

Excel 执行器本身已经把工作表不存在、尺寸不匹配和 Office.js/COM 错误转换为普通工具结果，模型可以在下一步修正。服务端预校验错误应采用同一恢复语义，同时不能让无效参数进入 Office.js 或原生 `.xls` 管道。

## Goals / Non-Goals

**Goals:**

- 让具有稳定调用 ID 的模型工具错误自动反馈给模型并继续任务。
- 接受常用且明确的整列、整行 A1 范围。
- 继续保证无效调用不执行、修改工具遵循审批模式、失败不留下已知部分写入。
- 对四种模型协议保持同一恢复行为并继续受用户配置的步骤上限约束。

**Non-Goals:**

- 不猜测或静默改写模型参数后直接执行。
- 不允许任意命令、脚本、工作表限定地址、联合范围或外部工作簿引用。
- 不自动批准修改工具，不降低来源、凭据、只读工作簿或历史上下文保护。

## Decisions

### 在服务端生成失败工具结果

函数调用解析返回可执行调用和可恢复错误两组结果。对具有唯一非空 `call_id` 的未知工具或参数校验错误，服务把原始模型输出保留在会话输入中，并追加匹配的 `function_call_output`：

```json
{
  "ok": false,
  "error": {
    "code": "RANGE_ADDRESS_INVALID",
    "message": "$.address 必须是有效 A1 范围。",
    "path": "$.address",
    "recoverable": true
  }
}
```

若同一模型步骤只有错误调用，服务立即发起下一模型步骤；若同时存在有效调用，服务等待有效调用经过现有审批与执行流程，再把有效和错误结果一并用于下一步。选择服务端恢复而不是前端放宽校验，可确保无效参数永远不跨入 Office.js 或 COM 信任边界。

### 只对可建立结果关联的错误恢复

缺失或重复 `call_id` 无法可靠形成一一对应的工具结果，继续可能污染协议历史，因此仍终止并清理会话。前端提交结果数量、名称或调用 ID 不匹配代表本地状态损坏，也继续失败关闭。提供方、配置、来源验证和用户取消错误不属于模型参数修正范围。

### 恢复步骤计入统一步骤上限

自动修正的每次模型请求都增加现有 `stepCount`。服务使用循环而非无界递归推进，并在每次新请求前读取当前有效上限。这样错误模型不能通过恢复路径绕过默认 100 步或用户配置的 1 到 1000 步上限。

### 扩展明确的 A1 范围而不接受任意表达式

共享校验器接受四种形式：单个单元格、单元格矩形、整列范围和整行范围，并允许 `$` 绝对标记。工作表名仍使用独立参数；联合范围、外部引用、命名范围和公式表达式仍不进入执行器。大范围读取继续由单元格数量限制阻止，格式化和自动行列宽可以使用整列或整行范围。

### 保持安全与配置边界

恢复错误只包含固定代码、校验路径和脱敏消息，不包含 API Key、请求头或提供方原始响应。DPAPI 持久化、回环 HTTPS、Origin/Host 校验、审批模式和原生 `.xls` 当前用户管道保持不变；Excel WebView 仍接触不到模型令牌。

## Risks / Trade-offs

- [较弱模型反复生成同一错误] -> 每次重试计入步骤上限，达到上限后清理会话并明确报错。
- [模型输出同时包含有效和无效调用] -> 只执行有效调用，无效调用预先记录失败结果，下一模型步骤同时看到全部对应结果。
- [整列读取产生巨大范围] -> 保留读取单元格上限并把超限结果反馈给模型分块读取。
- [协议适配器对未知工具结果形状敏感] -> 使用模型自己返回的 `call_id` 和原始函数调用历史；为统一归一化输入增加多协议请求形状测试。

## Migration Plan

无需数据迁移。部署时重启本地服务即可使用新循环；回滚只需恢复会话解析逻辑和旧地址校验，内存会话会随服务重启清除。
