## Context

模型发现接口通常只返回模型 ID。当前本地服务只在上游额外返回能力字段时使用它们，否则以协议和模型名称正则推断思考等级；上下文长度没有本地后备。设置页切换模型不会回填上下文，并且会重新启用思考等级下拉框。保存接口也接受客户端提交的任意受支持思考等级，因此禁用页面控件本身不能保证配置不可被篡改。

官方资料的格式和更新频率并不统一。以截图中的 `qwen3.7-max` 为例，阿里云百炼的模型页明确给出 1,000,000 tokens 上下文和思考模式限制，但 OpenAI 兼容 `/models` 响应不要求返回这些字段。

## Goals / Non-Goals

**Goals:**

- 用版本受控、可审查的本地目录为常用官方模型补全上下文和思考能力。
- 为同一模型使用一致的能力结果：模型发现、设置保存、配置恢复和会话临时切换均通过同一个解析路径。
- 选择模型时回填官方上下文，仍允许用户在保存前修改该数值。
- 使设置页思考等级只读，并由服务端从模型能力导出最终值，避免客户端绕过。

**Non-Goals:**

- 不在运行时抓取厂商网页、不增加模型 ID 或令牌向第三方的请求，也不引入云端同步。
- 不将任意上游别名推测为官方模型；目录外型号继续采用上游声明或现有保守推断。
- 不在本变更中扩展各厂商专有的推理参数协议，或移除对话编辑器现有的按消息思考选择。

## Decisions

### 1. 建立独立、数据驱动的官方能力目录

新增服务端模块，按协议和规范化模型 ID 返回 `contextWindow`、允许的 `reasoningEfforts`、固定 `defaultReasoningEffort` 或 `provider-default` 自动模式、来源和官方资料链接。目录记录精确型号或经过审查的系列匹配规则，首先覆盖截图所示的 Qwen3.7 Max，并收录项目支持协议的常用官方模型。

选择本地目录而不是运行时网页抓取，因为前者离线可用、可测试、不会泄露模型 ID，也不会使设置页受页面结构或厂商访问限制影响。目录条目在代码审查时必须带官方来源，后续型号更新通过常规发布更新。

### 2. 统一能力合并优先级

模型目录构建使用 `official -> provider -> inferred` 的优先级：官方命中时上下文和思考能力均以目录为准；未命中时才采纳上游明确元数据，再退回现有协议保守推断。每个规范化模型条目都有 `contextSource`、`reasoningSource`、`reasoningMode` 和 `defaultReasoningEffort`，便于页面准确说明信息来源。

官方只声明思考模式、未声明标准等级枚举的模型使用 `reasoningMode: "provider-default"`、空等级数组和空默认值。以 Qwen3.7 Max 为例，阿里云百炼官方模型页公开其思考模式和思维链限制，但不公开 `reasoning_effort` 枚举；因此系统显示“自动（提供方默认）”且不发送该参数，不把它臆测为 `high`、`medium` 或 `none`。

目录外的上下文不伪造默认官方值。当前已保存模型可继续使用其手动上下文；临时切换到另一个模型时优先使用该模型条目自己的上下文，避免把前一模型的覆盖值用于新模型。

### 3. 思考等级由服务端固定

设置页仅展示模型的默认思考等级或提供方自动状态并保持控件禁用。前端不再把该字段作为可编辑设置提交；`RuntimeConfigStore.update()` 对旧客户端或手工请求同样从模型条目导出默认值或自动状态，而不采信请求体中的 `reasoningEffort`。配置恢复也会根据目录重新导出思考等级，使历史手工选择自然迁移。

这比仅限制浏览器控件更可靠，同时保留现有对话编辑器的逐消息能力选择，避免超出截图所示设置表单的范围。

### 4. 上下文的回填与用户覆盖分离

在用户实际改变模型选择或成功刷新模型列表时，页面用模型条目的官方上下文回填输入框；输入框不禁用，用户随后修改的值会随当前保存模型持久化。重新打开已保存配置时保留该手动覆盖。运行时若消息临时选择不同模型，则使用所选模型目录上下文，而不是当前保存模型的手工覆盖。

## Risks / Trade-offs

- [官方模型更新或别名改名] → 仅对可识别的官方 ID 应用目录，目录外明确标为上游或推断来源，并为目录解析写回归测试。
- [网关复用官方 ID 但实现不同] → 保持用户可修改上下文；思考等级固定为目录默认值或自动状态，出现兼容性问题时用户应选择正确的协议/模型而不是伪造能力。
- [旧持久化配置包含过期思考等级] → 恢复时以当前模型目录默认值规范化，API Key 的 DPAPI 存储和其它设置不迁移或外传。
- [临时切换模型] → 在 `loadConfig({ model })` 中解析模型条目上下文，并增加测试覆盖会话使用的配置结果。

## Migration Plan

1. 部署后，下一次模型发现和设置恢复会使用新的目录重建模型条目。
2. 现有自定义配置的 API Key、协议、模型和手工上下文保持不变；已保存的思考等级被模型默认值替换。
3. 若发生回归，删除或收紧对应目录条目即可恢复上游/推断降级，不需要迁移或删除用户配置。

## Open Questions

无。目录只承诺已核验的常用模型；新增厂商型号通过后续官方资料更新，不把未核验名称视为官方能力。
