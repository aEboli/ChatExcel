## Why

当前模型发现主要依赖上游 `/models` 返回的可选元数据；仅返回模型 ID 时，设置页无法可靠地显示该模型的官方上下文长度和思考能力，用户还可能手动保存不适用的思考等级。模型选择应以受维护的官方能力目录为准，并在缺少目录条目时清楚地降级。

## What Changes

- 在本地服务中增加按协议和模型 ID 匹配的官方模型能力目录，包含常用上下文长度及支持的思考等级；官方未公布等级枚举的模型明确使用提供方自动模式。
- 获取模型列表时优先用目录补全或覆盖上游未声明的能力元数据，并保留来源标识和安全的未知模型降级。
- 设置页在选择模型后自动回填目录上下文长度；上下文长度仍可手动调整。
- 设置页显示模型决定的思考等级或提供方自动模式但不允许编辑，保存时服务端也只接受该模型的默认值或自动状态。

## Capabilities

### New Capabilities
- `model-capability-catalog`: 为已发现模型提供本地、官方来源的上下文长度和思考等级，并将其安全地应用到配置保存和任务窗格设置页。

### Modified Capabilities

<!-- 无。 -->

## Impact

- 影响 `src/server/runtime-config.js`、协议/模型能力映射及其单元测试。
- 影响 `src/taskpane/taskpane.html`、`src/taskpane/taskpane.js` 的模型选择、上下文回填和思考等级控件。
- 不增加上游 API 调用，不改变令牌存储边界；模型 ID、上游元数据和能力目录仅在本地服务与任务窗格的既有本地接口中流转。
