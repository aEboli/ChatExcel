## Context

`ProviderClient.create()` 目前只向上游发起一次请求。网络切换会使连接建立或正在读取的 SSE 连接发生传输错误，随后整个 `SessionManager` 会话被清理并在任务窗格中显示“无法连接当前模型提供方”。本机任务窗格到回环 HTTPS 服务的 SSE 断开仍代表客户端不再等待，必须继续取消会话，不能与上游重连混淆。

## Goals / Non-Goals

**Goals:**

- 让同一个尚未得到完整模型响应的上游步骤在临时传输断连后自动恢复。
- 首次失败后固定等待 3 秒，最多执行 10 次重连，并在每次等待期间响应用户停止和既有总超时。
- 让流式任务在重试时不把上一次未完成的文字与新尝试的文字拼接在一起。
- 保持令牌、本地回环网络边界、工具审批和失败关闭语义。

**Non-Goals:**

- 不重试 HTTP 鉴权、限流、业务错误、无效响应或提供方明确发送的 SSE 错误。
- 不改变本机任务窗格客户端主动断开时取消会话的行为。
- 不为重连增加用户可配置项、持久化任务数据或额外依赖。

## Decisions

### 在 ProviderClient 内重放单个模型请求

重连循环位于协议适配后的 `ProviderClient`，用完全相同的端点、请求体和外部中止信号重新发起当前模型步骤。`SessionManager` 只会在收到完整规范化响应后解析工具调用，因此失败尝试不会重复执行 Excel 工具。

不在任务窗格重发本地 `/api/sessions` 请求，因为本机 SSE 客户端断开已有取消语义，重复 HTTP 会话请求还会引入会话 ID 冲突和重复工具执行风险。

### 使用总超时和可中止固定延迟

一个组合后的 `AbortSignal` 覆盖首次请求、每次重连和两次请求之间的等待；300 秒等既有 `timeoutMs` 表示整个模型步骤的总上限。传输错误发生后先发送第 N/10 次重连状态，再等待 3,000 ms。第 10 次重连仍失败后，服务才返回既有脱敏 `PROVIDER_UNAVAILABLE` 错误。

不为每次尝试重新开始超时计时，避免坏网络把一个步骤延长为数十分钟。

### 严格区分可恢复传输错误与终态错误

仅连接建立失败及读取响应体时的 socket/网络中断进入重连循环。EOF 前未完成的 SSE 帧属于传输中断；已由空行终止的帧出现无效 JSON、空结构或协议字段错误则立即失败。无 `event:` 行但载有 `error` 的上游 SSE 负载同样是显式错误。仅明确的 socket/DNS 错误与标准 `fetch` 网络错误可触发建连重试；请求头、令牌或其他请求配置错误必须立即失败。外部取消、内部超时、非成功 HTTP 响应、JSON/协议格式错误以及提供方显式的 SSE `error` 事件沿用当前立即失败逻辑。错误摘要仍经现有脱敏逻辑处理，重连事件中不包含端点、令牌或原始错误内容。

### 用本地流式事件重置未完成草稿

若断开的流式尝试已产生文字增量，服务先发送带有本次尝试文字长度的 `stream_reset`，任务窗格仅撤销该长度对应的消息后缀；然后发送 `provider_reconnecting`，其中只有当前重连次数、最大次数和固定等待时长。这样同一任务较早模型步骤已经显示的文字不会被后续步骤的断线重置删除。下一次有效文字增量继续追加到保留的草稿；最终 `assistant_message` 仅替换当前模型步骤的流式文字后缀，并保留较早步骤的文字。

当服务因未知或无效工具调用自动追加可恢复结果并直接进入下一模型步骤时，它会发送无内容的 `model_step_boundary`。任务窗格以此清空当前步骤的文字长度，避免缺少 `tool_pending` 时将下一步终态错误地覆盖到较早步骤文本上。

这比在服务端缓存所有增量直到成功更合适，因为正常任务仍可实时显示文字；也比根据文本内容猜测重复片段更可靠。

## Risks / Trade-offs

- [上游可能对已收到但未完成的请求计费] → 仅处理网络中断，固定限制为 10 次，且不自动重试 HTTP/业务错误。
- [重试后模型响应与中断前不同] → 仅删除中断尝试的文字后缀，只展示成功尝试的新增文字；工具仍在完整响应后才执行。
- [网络长时间不可用] → 总超时仍限制整个步骤，重连耗尽后给出原有脱敏失败提示。
- [用户点击停止恰好发生在等待期间] → 延迟监听同一中止信号，不再发起后续请求。

## Migration Plan

该变更不涉及数据迁移或配置格式变更。部署后新启动的本地服务直接使用固定重连策略；回滚只需恢复原 ProviderClient 的单次请求行为。
