## Context

ChatExcel 将 Excel WebView、仅回环的 Node.js 服务、多个提供方协议和原生 `.xls` COM 宿主组合为一个本地运行时。现有实现能完成基本工作流，但进程身份、快照生命周期、上游协议完整性和 Excel 应用级状态之间存在隐含共享：旧服务可通过仅检查 `ok` 的健康接口被误认为新版本，清理进程可删除原子替换后的新快照，畸形的成功 HTTP 响应可被转换为空回答，且原生宿主可从另一个打开的工作簿读取或撤销操作。

本次变更保持模型令牌只在服务端、服务只监听 `127.0.0.1`、恢复数据只经 DPAPI 加密保存的既有边界。运行中的本地服务不作为部署目标；改动通过静态检查、定向测试和构建产物验证，实际替换服务须由用户单独授权。

## Goals / Non-Goals

**Goals:**

- 让启动、守护和停止流程只管理具有预期版本、能力、监听地址和进程身份的 ChatExcel 服务。
- 让恢复快照的写入、心跳和过期删除在服务及独立清理进程并发时保持线性化，不删除较新的快照。
- 让提供方响应、错误摘要和 Anthropic thinking 工具续传在不泄露凭据的情况下失败关闭。
- 让原生 `.xls` 宿主只操作 Launcher 绑定的工作簿，并在 COM、WebView2 和 smoke 失败中保留用户文件与 Excel 进程边界。
- 让发布版本、程序集元数据、服务健康状态和发行包从 `package.json` 的同一版本值派生。

**Non-Goals:**

- 不改变四种提供方对外端点、Excel 工具 Schema、审批策略或步骤上限。
- 不接管、终止或替换任何非本项目进程，也不在本次改动中重启当前本地服务。
- 不将恢复缓存扩展为历史会话、跨设备同步或明文调试日志。
- 不改变用户正常关闭原生窗格时继续控制 Excel 和未保存工作簿的行为。

## Decisions

### 使用版本化健康握手和进程身份记录

健康接口保留可读的 `ok`，同时返回固定 `service` 标识、发行版本和所需 capability 列表。启动脚本、守护器和 Launcher 从 `package.json` 取得预期版本，只有当 `127.0.0.1` 的监听进程、健康响应和预期协议全部匹配时才认为服务可用。运行时 PID 文件记录 PID、进程启动时间和版本；停止或恢复前重新验证这些值以及受管启动命令的项目归属。

这比仅验证端口或 PID 更能阻止 PID 复用、IPv6/LAN 同端口监听和旧内存服务混入新静态资源。检测失败只报告冲突或不匹配，不杀死未知进程；显式停止仅清理由本项目启动且仍匹配的进程。

### 使用所有恢复操作共享的文件锁完成条件删除

`ConversationRecoveryStore` 在写入、心跳、显式清除和过期清理前取得同目录的原子排他锁。锁持有期间重新读取当前加密文件、验证会话或过期条件，再执行写入或删除；锁在 `finally` 中由拥有者释放。锁获取采用短暂有界等待，并仅回收可证明失效的陈旧锁，失败时返回恢复不可用而不使用未保护的删除回退。

因此清理工作进程无法在读取旧文件后删除另一个进程刚刚原子替换的新文件。任务窗格本地 SSE 传输错误标记为可恢复会话断开，保留现有 session ID；显式清除仅在服务确认删除后清空本地状态。Office 工作簿每次恢复前重新获取稳定绑定，原生 `.xls` 不使用随机管道会话 ID 作为持久绑定。

### 用共享认证脱敏器和协议终态校验隔离上游输入

运行时配置、模型发现和生成调用都通过一个保守的认证信息脱敏器处理可展示错误。它覆盖 Bearer、Basic、常见 API key 头及 JSON/查询认证字段，并在已知配置令牌之外隐藏疑似凭据值。错误只保留状态、短摘要和规范错误码。

每种非流式和流式适配器在交给 `SessionManager` 前验证其协议根结构、候选/内容终态和工具调用形状。HTTP 200 但缺少可归一化终态的响应抛出 `PROVIDER_RESPONSE_INVALID`，不重连也不伪装成空助手消息。Anthropic 流累积器按 content block 保留 `signature_delta`，并保留 `redacted_thinking`，使下一轮工具续传能原样回传连续 reasoning block。

### 将原生 COM 操作绑定到指定工作簿窗口

原生执行器从受绑定工作簿的窗口取得 Selection/ActiveCell，并通过工作簿父对象过滤工作簿级事件。应用级 Undo 在绑定工作簿不是活动工作簿时明确失败，避免撤销另一文件的用户操作。所有临时 COM 对象仍在 `finally` 中释放。

数字格式写入先计算实际行列总数并拒绝超过 5,000 个单元格；读取到 Excel 对混合 `NumberFormat` 返回的空值时，在既有读取上限内逐单元格取得格式。表格的后续命名或样式失败使用 `Unlist` 保留源数据。打开失败仅退出本次新建的 Excel 实例；关闭事件延迟到 Excel 确认工作簿已实际移除后才销毁窗格；WebView2 初始化失败传播到 Launcher 的非零退出码。

### 发行构建失败关闭，并隔离 smoke 输入

构建脚本检查 `npm install` 和 `dotnet publish` 的退出码，只有所有必需步骤成功后才生成发行目录。发布时将 `package.json` 版本作为 MSBuild 的 `Version`、`AssemblyVersion` 和 `FileVersion` 传入，并检查产物元数据。原生 smoke 在临时副本上保存和重开工作簿，原始输入只用于复制和哈希核验。

### 只为真实执行结果创建历史预览

任务窗格在构造网格或图表预览前先检查工具输出的成功状态。用户拒绝、参数校验失败或执行失败的修改操作只显示只读失败说明，不能从请求参数推导出仿真的已写入网格。

## Risks / Trade-offs

- [跨进程锁因异常残留而暂时阻塞恢复] → 使用有界等待、可证明失效的锁回收和不泄露内容的恢复不可用状态。
- [更严格的健康协议拒绝旧服务] → 明确报告版本或能力不匹配，保留用户授权后再替换服务的运维边界。
- [严格协议校验暴露兼容网关缺陷] → 返回可诊断的 `PROVIDER_RESPONSE_INVALID`，不重试已完整但无效的响应。
- [应用级 Undo 无法在切换工作簿后执行] → 返回可恢复错误而不是破坏另一个工作簿，用户可激活绑定工作簿后重试。
- [真实 Excel/ WebView2 行为受本机环境影响] → 自动化测试覆盖逻辑分支，另外保留明确的桌面验收项。

## Migration Plan

1. 发布新服务时使用新的健康字段和 PID 元数据；发现旧服务后停止脚本只报告不匹配，维护者在获得授权后执行现有受控停止/启动流程。
2. 现有恢复文件仍使用同一路径和 DPAPI 信封；首次操作由新锁协议串行化，无需迁移明文或会话数据。
3. 发行构建开始传递版本属性，直接 `dotnet build` 仍保留项目文件中的开发默认值。
4. 回滚时旧服务会忽略新增健康字段；新 PID 元数据和锁文件不包含凭据，过期锁可由新版本清理。
