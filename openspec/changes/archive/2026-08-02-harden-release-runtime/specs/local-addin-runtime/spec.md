## ADDED Requirements

### Requirement: 版本化的受管服务就绪验证
项目启动脚本、守护器和 Launcher MUST 仅在 `127.0.0.1` 上的目标端口由 ChatExcel 服务监听，且健康响应同时匹配预期 `service` 标识、由 `package.json` 派生的版本和所需 capability 时，才将服务视为就绪。健康响应不得包含凭据或工作簿内容。

#### Scenario: 端口保留旧版本服务
- **WHEN** 目标端口的服务返回 `ok: true`，但版本或 capability 与当前发行物不匹配
- **THEN** 启动流程将其报告为不匹配服务，而不得用该服务加载新任务窗格或覆盖其 PID 记录

#### Scenario: 非回环监听同端口
- **WHEN** `::1`、LAN 地址或其他非 `127.0.0.1` 地址监听目标端口
- **THEN** 启动、守护和停止流程不得把该监听者认定为本项目服务或向其发送终止信号

### Requirement: 受管进程身份必须可复核
守护器和停止脚本 MUST 将受管服务记录为 PID、进程启动时间和发行版本，并在恢复、停止或清理该记录前重新验证这些值、回环监听和项目启动命令归属。身份不匹配时 MUST 保留进程并返回可诊断的冲突状态。

#### Scenario: PID 被系统复用
- **WHEN** PID 记录中的数字已指向启动时间或命令归属不同的 Node.js 进程
- **THEN** 脚本不得停止、接管或删除该进程，只清理失效的本项目记录并报告身份不匹配

#### Scenario: 用户显式停止受管服务
- **WHEN** `npm run stop:local` 找到仍匹配记录、监听和版本的受管服务
- **THEN** 它先停止守护器，再停止该服务并清理本项目运行时记录，守护器不会重新拉起该服务
