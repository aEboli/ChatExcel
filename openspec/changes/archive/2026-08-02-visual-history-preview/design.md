## Context

操作记录当前在点击后只过滤任务窗格中的对话消息。它没有工作簿快照或可靠的反向工具执行记录；将真实 Excel 工作簿恢复到任意步骤会产生未保存修改，并可能在启用自动保存时被持久化。

## Goals / Non-Goals

**Goals:**

- 在用户点击任一操作记录时，显示该步骤完成瞬间的表格或图表视觉状态。
- 让视觉状态只存在任务窗格页面内存，不修改 Excel 工作簿、不调用保存，也不离开前端页面。
- 在截图不支持或不可用时继续提供范围数据的只读网格回退，并使预览失败不影响 Agent 工具循环。

**Non-Goals:**

- 不回滚、分支、保存或恢复真实 Excel 工作簿。
- 不把截图或范围数据追加到模型工具结果、会话恢复记录、服务端、日志或用户级设置。
- 不为原生 `.xls` 引擎实现 COM 层的工作簿截图或跨步骤撤销。

## Decisions

### 在工具完成与下一工具开始之间捕获

`AgentRunner` 将接受可选的前端预览捕获回调。执行器返回工具结果后、发布 `tool_completed` 事件前调用该回调，并只把结果附在前端事件上。这样预览对应准确的步骤时间点，且 Base64 图像不会作为 `output` 被提交给模型或服务端。

### 使用范围或图表图像，并为大范围裁剪

Office.js 模式下，使用 ExcelApi 1.7 的 `Range.getImage()` 或 `Chart.getImage()` 获取 Base64 PNG。范围在读取尺寸后裁剪到有限行列，过大的图像回退为文本/网格预览，避免一个操作耗尽任务窗格内存。读取、写入、格式、清除、建表、排序和建图都根据已验证的工具参数和实际输出确定目标；无目标、失败或拒绝步骤显示明确的只读说明。

备选方案是把快照重新写回 Excel 并禁止保存。该方案被拒绝：它会令工作簿变脏，无法阻止用户或自动保存机制持久化预览状态，且表格、图表、排序和工作表操作没有统一可靠的逆操作。

### 预览绑定活动记录而不进入恢复路径

每个 `HistoryState` 活动条目可携带一个内存预览。任务窗格独立记录当前被点击的活动索引，使最新步骤也能显示预览，但只有非最新步骤继续触发既有历史上下文保护。刷新、清空会话和恢复旧展示消息时均丢弃预览；恢复接口继续只处理展示消息。

### 为原生 `.xls` 提供数据网格回退

原生桥没有 Office.js 图像 API。对有确定范围的成功步骤，任务窗格只读请求该范围并在页面内渲染有限网格；失败时回退到现有工具输出或安全说明。该辅助读取不创建操作记录、不改变修订号，也不发送给模型。

## Risks / Trade-offs

- [每个步骤的 PNG 增加页面内存] → 裁剪范围并拒绝超出单张上限的图像，随后显示轻量网格或说明。
- [图像 API 在部分 Excel 宿主失败] → 捕获失败被隔离，不影响原工具结果，并显示可用的范围数据或只读说明。
- [用户把预览误认为真实工作簿回滚] → 历史横幅明确说明预览只存在任务窗格且不会修改或保存工作簿。
- [`.xls` 无图表图片回退] → 显示可读范围数据或步骤说明，不模拟或修改原生工作簿。

## Migration Plan

1. 部署任务窗格脚本与样式后，新步骤自动开始捕获预览；旧会话没有预览并显示安全说明。
2. 回滚仅需恢复此前任务窗格静态资源；预览从未写入工作簿或服务端，无需数据迁移或清理。
