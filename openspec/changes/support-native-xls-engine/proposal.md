## Why

Microsoft Excel 的 Office.js 任务窗格不能附着到 Excel 97-2003 `.xls` 工作簿。把旧文件转换成 `.xlsx` 虽然能加载现有任务窗格，但会改变用户文件格式，也无法满足直接处理原始 `.xls` 的需求。

ChatExcel 需要在不伪装 Office.js 兼容性的前提下提供第二条本地执行路径：现代工作簿继续使用 Office.js，`.xls` 由 Launcher 内置的原生 Excel 自动化引擎处理，并复用同一套 ChatEx 对话、审批、模型配置和操作记录界面。

## What Changes

- Launcher 接受一个工作簿路径，并按扩展名自动分流：`.xls` 使用原生引擎，`.xlsx`、`.xlsm` 和 `.xlsb` 使用现有 Office.js 侧载流程；无路径启动保持现有行为。
- 增加 Windows Excel COM 工作簿执行器，在原始 `.xls` 中实现现有读取、写入、格式、工作表、表格、图表和排序工具，不创建转换副本、不改变扩展名。
- Launcher 使用内置 WebView2 窗口承载现有任务窗格页面，并把窗口与本次 Excel 实例关联；配置、对话、图片、流式输出、审批和操作记录继续使用现有实现。
- 增加仅限当前 Windows 用户、每次启动随机命名的本地管道桥。任务窗格通过回环 HTTPS 服务把经过既有参数校验的工具调用转发给原生引擎。
- 监听原生 Excel 的工作表修改与激活事件，使历史上下文保护和当前工作簿标签在 `.xls` 模式继续生效。
- 更新发行打包、诊断、测试和中英文文档，说明两种引擎的触发方式和 `.xls` 兼容模式边界。

## Boundaries

- 不修改 Microsoft Office 加载项清单来声称 `.xls` 支持；Office.js 仍只负责受支持的现代工作簿。
- 不转换、覆盖、复制或自动另存 `.xls`。用户仍通过 Excel 原生保存流程决定是否保存修改。
- 原生引擎只连接 Launcher 本次打开的一个绝对路径 `.xls` 工作簿，不接受 URL、脚本或任意进程控制命令。
- 不新增局域网或公网监听；工作簿内容、提示词、工具结果和管道会话标识不写入 Launcher 日志。
- `.xls` 自身不支持的 Excel 新格式特性由 Excel 兼容模式决定；工具无法完整执行时必须失败关闭，不得静默转换格式或留下已知的部分写入。
