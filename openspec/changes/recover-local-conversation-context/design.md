## Context

当前 `SessionManager` 将模型输入、工具循环状态和会话 ID 仅放在 Node.js 进程内存中，`AgentRunner` 也仅把会话 ID 保存在任务窗格脚本内。任务窗格刷新、本地服务重启、最终提供方错误或 Excel 异常退出会让后续消息创建新会话，而旧气泡不能为模型提供上下文。项目现有的 `SettingsStore` 已使用 Windows DPAPI 和同目录临时文件加 rename 的原子写入模式保护 API Key；恢复缓存必须复用该安全模型，但不能混入可漫游的配置文件。

本变更是用户明确授权的窄范围例外：保留当前会话以恢复崩溃，不建立长期聊天历史、云同步或遥测，也不改变模型令牌只存在本地服务进程的边界。

## Goals / Non-Goals

**Goals:**

- 在当前 Windows 用户的本地磁盘上保存一份可恢复的当前工作簿会话，支持任务窗格刷新和本地服务重启。
- 用由任务窗格存活心跳维护的 30 分钟租约删除恢复缓存：任务窗格持续打开时即使用户不聊天也保持有效；任务窗格或 Excel 窗口关闭或崩溃后，从最后一次成功心跳起 30 分钟删除。用户显式停止、重置或清空时立即删除。
- 在每个模型请求前、模型输出/工具结果进入输入历史后和中断时写入可恢复快照。
- 恢复后绝不自动调用提供方、执行 Excel 工具或重放 Excel 写入；任何未完成工具调用必须被标为中断并要求重新读取或重新审批。

**Non-Goals:**

- 不实现跨设备、跨 Windows 用户、跨工作簿的聊天历史或对话列表。
- 不调整上游模型的实际上下文长度，也不实现上下文摘要或自动截断策略。
- 不保存 API Key、Authorization 头、网络端点日志或遥测数据到恢复缓存。
- 不尝试判断崩溃瞬间 Excel 写入是否已部分生效；恢复后的模型必须重新读取工作簿再决定下一步。

## Decisions

### 使用单独的 DPAPI 加密恢复文件

新增 `ConversationRecoveryStore`，默认写入 `%LOCALAPPDATA%\\ChatExcel\\conversation-recovery.json`，而不是 `%APPDATA%` 的 `settings.json`。外层文件只包含版本和 DPAPI 密文；快照 JSON（模型输入、会话选项、步骤计数、待工具调用、工作簿绑定、最后一次成功任务窗格存活心跳时间和恢复阶段）始终以 `DataProtectionScope.CurrentUser` 加密。写入沿用同目录临时文件和原子 rename；恢复缓存的 TTL 仅根据该心跳时间检查，模型请求、工具执行、快照保存或用户消息均不得续期。

生产服务在首次写入前启动一个无窗口、脱离主服务的同用户清理进程。它使用同一加密存储检查任务窗格存活租约，因此主服务闪退后仍会在最后一次成功心跳起 30 分钟后删除正式密文文件；它也会清理原子写入在崩溃时遗留的同目录 `.tmp` 密文。若子进程异步启动失败，服务必须消化该错误、释放失败引用，并在下一次保存或成功心跳时重新尝试启动。DPAPI 暂不可用时，清理只使用密文文件自身的最后写入时间判断过期，不读取或暴露负载；用户显式清空时则立即删除正式文件及匹配的临时密文。

只保存一个当前工作簿绑定的快照。开始另一个工作簿会话会替换旧快照，这与“仅当前滑动上下文”保持一致，也避免形成未受控的历史列表。使用 Office 文档 URL 作为工作簿稳定标识，绑定本身只出现在加密负载中；无法获得稳定标识时禁用恢复，而不使用易冲突的工作簿名称。

备选方案是在任务窗格 `localStorage` 保存完整对话或复用设置文件。前者以明文保存且无法覆盖服务崩溃，后者会把高频且短期的任务数据混入可漫游配置，因此均不采用。

### 将恢复检查点放在 SessionManager，而非任务窗格

`SessionManager` 负责创建所有实际发送给模型的 `input`、模型 `output`、工具结果和待工具调用，因此在这里构建快照。它不序列化 `AbortController`、流式回调或其他运行时对象，只序列化 JSON 安全的会话字段。每次模型调用前先写入“模型请求中”标记；模型响应/工具结果进入历史后再更新快照。这样服务在调用提供方或等待 Excel 时崩溃，至少保留最后一个可解释的状态。

任务窗格只负责提供工作簿绑定、恢复显示已有用户/助手文本、恢复 session ID，以及在保持打开期间定期发送心跳。创建或恢复时会初始化一次窗格存活租约，此后只有成功且与会话匹配的心跳可以续期，因此窗口持续打开时即使不聊天也不应过期；窗口关闭或崩溃后不依赖 `beforeunload`，最后一次成功心跳自然成为 30 分钟倒计时起点。它不接触 DPAPI、模型令牌或恢复文件路径。

备选方案是让任务窗格上传完整 UI 状态。该方案不能覆盖服务端模型请求前的崩溃，也会产生两份不一致的上下文来源，因此不采用。

### 为断开、取消和失败区分三种生命周期语义

显式停止/重置调用 `cancel`，中止运行并删除恢复记录。SSE 客户端异常断开改为 `suspend`：先记录中断阶段、从内存会话表移除并中止正在运行的提供方请求，但不删除加密快照。提供方终态错误保留可恢复的空闲会话和快照，并把错误标为可继续，因此用户下一次明确发送消息仍能复用同一上下文。

正常服务关闭对所有活动会话执行与异常断开相同的挂起检查点，再中止请求并释放内存，不删除恢复文件；新的服务进程通过受信任任务窗格 API 重建会话。用户显式取消会设置终态标记，使迟到的提供方响应不能再次写入已清除的恢复文件。现有 30 分钟内存清理对具备工作簿绑定的可恢复会话使用任务窗格存活租约，对普通不可恢复会话仍按闲置时间清理，并同步触发恢复存储的过期清理；独立清理进程保证服务本身退出或崩溃后仍执行物理过期删除。

### 将未完成工具调用显式转换为安全失败结果

恢复快照若在模型请求中断，则恢复为空闲会话和“上次模型请求未重发”提示，不产生提供方调用。若快照正在等待工具结果，则恢复时把每个待调用转换为结构化 `TOOL_EXECUTION_INTERRUPTED` 结果并追加到模型输入，然后清除待调用。这既不会执行任何 Excel 工具，也使下一条用户显式消息能以协议完整的工具循环继续。

即使中断的工具是读取操作，也采用相同规则，因为工作簿可能已经改变。对于修改操作尤其不能假设未执行或再次执行；模型必须先重新读取并再次请求审批。

### 通过受同源保护的恢复 API 协调任务窗格

新增同源 JSON 端点用于恢复、心跳和显式清除。恢复请求按工作簿绑定返回当前快照或空结果，心跳只允许匹配的会话刷新最后一次成功任务窗格存活心跳时间，清除走既有会话取消路径。SSE 断开处理调用 `suspend`，而不是现有的破坏性 `cancel`。所有端点保持现有 Host、Origin、JSON 大小和本地回环限制，并设为不可缓存。

## Risks / Trade-offs

- [DPAPI 或磁盘写入失败导致无法保存恢复快照] → 不降级为明文；保留当前内存会话并向任务窗格给出不含敏感信息的恢复不可用状态。
- [恢复文件包含大图片或长工具结果] → 对序列化快照施加大小上限并拒绝持久化超限内容，不影响当前进程内会话。
- [缺少稳定工作簿标识] → 禁用恢复并在任务窗格说明原因，不以同名工作簿猜测恢复目标。
- [崩溃发生在 Excel 写入期间] → 不推断写入结果、不自动重试，转换为中断结果，要求后续模型重新读取和审批。
- [心跳无法在后台持续运行] → 任务窗格或 Excel 关闭或崩溃后不再有成功心跳，最后一次成功心跳满 30 分钟即删除缓存；任务窗格持续打开且心跳成功时，即使不聊天也不应过期，符合短期恢复而非长期保存的边界。

## Migration Plan

部署后，新启动的本地服务创建独立恢复存储和到期清理进程。不存在旧文件时不执行迁移；无效、无法解密或已过期的文件被安全删除并以空会话继续。回滚时可以停止引用恢复存储，遗留的 DPAPI 文件会由已启动的清理进程在期限后删除，且不会被旧版本读取。
