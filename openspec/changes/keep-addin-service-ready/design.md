## Context

任务窗格入口依赖本机 HTTPS 服务。当前 `scripts/start.ps1` 已具备进程归属、端口冲突、版本化健康检查和后台监督器逻辑，Launcher 也已有不会打开 Excel 的 `--service-only` 模式；缺口仅是成功安装后没有持久化任何登录启动入口。

## Goals / Non-Goals

**Goals:**

- 用户完成一次安装后，后续登录 Windows 并打开 Excel 时，点击 ChatExcel 不再因服务未运行而失败。
- 源码和发行 Launcher 复用同一套启动项所有权规则。
- 安装失败不留下半配置启动项，卸载不删除属于其他 ChatExcel 目录的启动项。

**Non-Goals:**

- 不让 Office.js WebView 直接执行 PowerShell、Node.js 或任意本机命令。
- 不新增 Windows 系统服务、计划任务、管理员安装器或原生 Excel 加载项。
- 不改变显式 `stop:local` 在当前登录会话内停止服务的语义。

## Decisions

### 使用当前用户 Run 启动项

新增固定脚本 `scripts/startup-registration.ps1` 管理一个固定值名。源码模式写入隐藏的 Windows PowerShell 命令并调用当前项目 `scripts/start.ps1`；发行模式写入带引号的当前 Launcher 路径和 `--service-only`。两种命令都复用现有服务启动及健康检查，不复制服务管理逻辑。

选择 `HKCU` Run 而不是 Windows 服务或计划任务，是因为它不需要管理员权限，符合当前按用户安装和证书信任边界。启动命令不包含模型令牌、工作簿路径或用户提示词。

### Office 入口使用服务实际监听的 IPv4 地址

服务已经只绑定 `127.0.0.1`，而 Windows 对 `localhost` 的解析可能优先返回未监听的 `::1`。因此 Office 清单和原生 `.xls` 伴随窗格都使用 `https://127.0.0.1:3210`。既有 Office 开发证书同时覆盖 `localhost` 和 `127.0.0.1`，并由现有证书校验脚本在启动前确认。

### 成功后注册，按精确命令删除

源码安装和发行 Launcher 只在服务与 Office 旁加载成功后注册启动项。卸载时先计算当前项目应拥有的完整命令，只有注册表中的现值与其完全一致时才删除；若其他目录或发行版已接管同名值，则保留并报告未删除。

源码卸载把启动项移除放在服务停止、加载项注销和项目文件清理之后。这样任一前置清理失败时，原启动项仍可用于恢复当前项目，避免留下无法修复的半配置状态。

### 登录启动保持无界面

发行版使用既有 `--service-only`：证书必须已经可信，失败时只返回非零退出码，不显示消息框，也不打开 Excel。源码命令使用 `-WindowStyle Hidden` 运行 `start.ps1`。首次证书安装仍只发生在用户主动运行安装器或 Launcher 时。

任务窗格在 Excel 初始化阶段仅对 `TypeError` 网络失败按 `250/500/1000/2000/3000ms` 重试；HTTP 错误、取消和配置校验错误立即失败并保留现有红色修复入口。

## Risks / Trade-offs

- 用户在任务管理器禁用启动项后，Excel 点击仍会遇到服务不可达；安装器可再次写入正确值，但不能绕过 Windows 的用户选择。
- 便携发行目录被移动或删除后，旧启动项路径会失效；用户再次从新位置成功运行 Launcher 时会覆盖为新路径。
- 当前用户登录时服务会常驻本机回环端口；监督器和服务仍受现有停止脚本及进程归属校验约束。

## Verification

- 在临时 HKCU 子键中执行安装、状态检查、异目录保护和卸载测试。
- 验证源码安装仅在旁加载成功后注册，卸载调用精确移除。
- 验证 Launcher 仅在默认/现代工作簿路径注册，`--service-only` 不递归注册或打开 Excel。
- 在真实环境停止服务后登记启动项、重新登录或执行已登记命令，确认版本化健康接口恢复，再从 Excel 点击 ChatExcel。
